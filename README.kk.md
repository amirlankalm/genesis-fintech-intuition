# Genesis FinTech: қаржылық аудит модельдеріне арналған RL ортасы

[English](README.md) · [Русский](README.ru.md) · **Қазақша**

**Intuition командасы · Genesis Hackathon 2026 (FinTech тапсырмасы: «Қаржылық аудит модельдерін қосымша оқытуға арналған RL орталары»)**

Біз — **Intuition командасы**. Міне, біздің шешім: ЖИ-аудиторларды қосымша оқытуға (post-training) және бағалауға арналған қайталанатын Reinforcement Learning (RL) жаттығу әлемі.

Шынайы қаржылық аудитте жасанды интеллект модельдерінің жай ғана жорамалдауға немесе жаңылуға құқығы жоқ: әрбір табылған қате нақты бастапқы құжаттармен және проводкалармен дәлелденуі тиіс. Біз Gym стандартына сәйкес келетін орта құрдық: мұнда детерминирленген генератор жасанды компанияның есептік кезеңдегі кітаптарын жазып, оларға шынайы бухгалтерлік қателер мен заңды шатастырушы жағдайларды (decoys) енгізеді. Агент 5 нақты құрал арқылы зерттеу жүргізеді, ал орта оның қорытындыларын жасырын жауап кілтімен қатаң бірге-бір bipartite matching алгоритмі және ресми сыйақы функциясы арқылы бағалайды.

> [!NOTE]
> **100% синтетикалық деректер:** Барлығы seed арқылы генерацияланады. Нақты компаниялардың, адамдардың, банктердің немесе карталардың деректері мүлдем қолданылмайды.

**Хакатон мерзімі:** Жоба хакатон барысында (2026 жылғы 19–20 қараша) әзірленді және тексерілді. Тапсырманың соңғы талаптарымен және 20 қарашада жарияланған ресми тексеру анықтамаларымен (`judge_adapter.py`, M01–M12 matcher ережелері, D01–D20 сценарийлері) толық сәйкестендірілген.

### Docker (тапсырмадағы шектеулер: 2 CPU, 4 GB RAM, желісіз)
```bash
make docker-check
```
Немесе тікелей Docker арқылы:
```bash
docker build -t genesis-audit-env . && docker run --rm --network none --cpus 2 --memory 4g genesis-audit-env
```

Docker-сіз (macOS немесе Linux, [uv](https://docs.astral.sh/uv/) орнатылған):
```bash
uv sync --frozen   # Python 3.11+; тәуелділіктер uv.lock ішінде бекітілген
make check         # lint, mypy, тесттер, self-check
make judge         # judge_adapter.py арқылы baselines және solver тексеру
```

Жұмыс каталогы: жоба түбірі (контейнерде `/app`). `uv sync` кейін желі қажет емес, GPU немесе ақылы API де керек емес.

## 🧠 Жүйе қалай жұмыс істейді

Шешім 5 негізгі қабаттан тұрады:

```
Seed + Конфиг ──► Бизнес-процестер симуляциясы ──► Балансталған таза кітаптар
                                                           │
                                                           ▼
                           4 қате отбасы + шынайы шатастырушылар (Decoys)
                                                           │ (provenance.json файлында)
                                                           ▼
                                  Ашық ережелер бойынша есептелген шындық
                                                           │
ЖИ-аудитор ◄── 5 құрал (reset/step) ── Кітаптар ──► Bipartite Matcher ──► Сыйақы
```

1. **Компанияның өмірлік циклі:** Алдымен тұтынушылар, валюталар және мәмілелер симуляцияланады. Қос жазу әдісі арқылы таза бухгалтерлік кітаптар құрылады.
2. **Қателерді енгізу:** Қателер бухгалтердің нақты қателіктерін көрсетеді (шоттардың көшірмелері, дұрыс бөлінбеген төлемдер, валюта бағамының қателері, кезеңдердің сәйкессіздігі). Әрбір өзгеріс `provenance.json` файлына жазылады.
3. **Шынайы decoys:** Бөліп төлеулер, қайтарулар және бірдей сомалы мерзімді төлемдер жүйенің қарапайым ережелермен алданбауын қамтамасыз етеді.
4. **Агент құралдары:** Агент тек 5 қауіпсіз құрал арқылы жұмыс істейді:
   - `list_records(table, cursor, limit)`: `ledger`, `invoices`, `payments`, `fx` кестелерін оқу.
   - `get_record(table, record_id)`: белгілі бір жазбаны немесе бағамды алу.
   - `get_document(doc_type, doc_id)`: бастапқы құжатты (шот немесе төлем) оқу.
   - `calculator(expression)`: дәл есептеулерге арналған қауіпсіз калькулятор.
   - `submit(findings)`: соңғы есепті тапсыру.
5. **Максималды паросочетание және бағалау:** Агенттің қорытындылары жасырын шындықпен максималды екіүлесті паросочетание (maximum bipartite matching) арқылы салыстырылады.
