# Genesis FinTech: қаржылық аудит модельдеріне арналған RL ортасы

[English](README.md) · [Русский](README.ru.md) · **Қазақша**

**Intuition командасы · Genesis Hackathon 2026 (FinTech тапсырмасы: «Қаржылық аудит модельдерін қосымша оқытуға арналған RL орталары»)**

Біз — **Intuition командасы**. Міне, біздің шешім: ЖИ-аудиторларды қосымша оқытуға (post-training) және бағалауға арналған Gym стандартына үйлесімді қайталанатын Reinforcement Learning (RL) жаттығу әлемі.

Шынайы қаржылық аудитте автономды агенттердің жорамалдарға немесе галлюцинацияларға сүйенуіне жол берілмейді: әрбір қате өзгермейтін бастапқы құжаттармен дәлелденуі керек, ал жалған айыптаулар аудит үшін өте қауіпті. Біз детерминирленген генератор компанияның есепті кезеңдегі құжаттарын жасап, шынайы бухгалтерлік қателер мен заңды шатастырушы жағдайларды (decoys) енгізетін, бес нақты зерттеу құралын ұсынатын және агент қорытындыларын жасырын ақиқатпен максималды екіүлесті паросочетание (maximum bipartite matching) алгоритмі арқылы бағалайтын орта әзірледік.

> [!NOTE]
> **Синтетикалық деректер:** Барлық контрагенттер, банк шоттары және мәмілелер детерминирленген PRNG seed арқылы генерацияланады. Нақты компания немесе төлем деректері мүлдем қолданылмайды.

**Мерзімі:** Жоба хакатон барысында (2026 жылғы 19–20 қараша) әзірленді және тексерілді. Тапсырма спецификациясына және 20 қарашада жарияланған ресми тексеру анықтамаларына (`judge_adapter.py`, M01–M12 matcher ережелері, D01–D20 сценарийлері) толық сәйкес келеді.

## Жылдам іске қосу

### Жергілікті іске қосу (Python 3.11+, uv)

```bash
uv sync --frozen   # бекітілген тәуелділіктерді орнату
make check         # lint, mypy, қамтуы бар pytest, өзін-өзі тексеру
make judge         # judge_adapter.py арқылы baselines және solver тексеру
```

### Docker арқылы іске қосу (автономды шек: 2 CPU, 4 GB RAM, желісіз)

```bash
make docker-check
```

Немесе make қолданбай тікелей Docker арқылы:

```bash
docker build -t genesis-audit-env . && docker run --rm --network none --cpus 2 --memory 4g genesis-audit-env
```

Барлық әрекеттер репозиторий түбірінен жергілікті орындалады (контейнер ішінде `/app`). Тәуелділіктер орнатылғаннан кейін желі қажет емес, сыртқы API немесе GPU қолданылмайды.

## Жүйе архитектурасы

Орта архитектурасы бизнес-логиканы, күй өзгерістерін, агент тексерулерін және ресми бағалауды бес тәуелсіз деңгейге бөледі:

```
Seed + Конфиг ──► Бизнес-процестер симуляциясы ──► Балансталған таза кітаптар
                                                           │
                                                           ▼
                           4 қате отбасы + шынайы шатастырушылар (Decoys)
                                                           │ (provenance.json файлында)
                                                           ▼
                                  Ашық ережелер бойынша есептелген шындық
                                                           │
ЖИ-аудитор ◄── 5 құрал (reset/step) ── Кітаптар ──► Bipartite Matcher ──► Сыйақы
```

1. **Компания симуляциясы:** Тұтынушыларды, мәмілелер кестесін, мультивалюталық бағаларды және бағамдар қатарын генерациялайды. Қос жазу әдісімен кітаптар (`ledger.csv`, `invoices.jsonl`, `payments.jsonl`, `fx.csv`) құрылып, дебет пен кредит толық балансталады. Барлық сомалар бөлшек сандардың дәлсіздігін болдырмау үшін минорлық бірліктерде (тиын, цент, иена) сақталады.
2. **Детерминирленген қателер енгізу:** Шынайы бухгалтерлік қателіктерді енгізеді (қос шоттар, төлемнің дұрыс бөлінбеуі, валюта бағамының қателері, кезеңдердің сәйкессіздігі). Әрбір өзгеріс `provenance.json` файлына жазылады.
3. **Шынайы шатастырушы жағдайлар (Decoys):** Модельдер қарапайым ережелерге сүйенбеуі үшін қайталанатын заңды төлемдер, бөліп төлеулер, қайтарулар және уақыт белдеулерінің ауытқулары сияқты жағдайлар қамтылған.
4. **Агенттің құралдары мен бақылауы:** Стандартты Gym интерфейсін (`reset` және `step`) іске асырады. Агент әрекеттері бес нақты құралмен шектелген:
   - `list_records(table, cursor, limit)`: детерминирленген курсорлармен парақтап оқу (бір бетте ең көбі 50 жол).
   - `get_record(table, record_id)`: бастапқы кілт бойынша жазбаны алу.
   - `get_document(doc_type, doc_id)`: бастапқы JSON құжатын алу.
   - `calculator(expression)`: дәл арифметикалық есептеулерге арналған қауіпсіз калькулятор.
   - `submit(findings)`: аудиторлық қорытындыны тапсыру.
5. **Екіүлесті паросочетание және бағалау:** Агенттің қорытындысы жасырын ақиқатпен максималды екіүлесті паросочетание алгоритмі арқылы салыстырылады.

## Бухгалтерлік қателер отбасы

Әрбір қате ережесі `policy.json` ішінде нақты анықталған және ашық құжаттар негізінде шешіледі:

| Қателер отбасы | Ортадағы `type` | `affected_ids` | Сома (`claimed_amount_minor`) | Минималды дәлелдер жиынтығы |
|---|---|---|---|---|
| **Шоттардың қайталануы** | `duplicate_invoice` | Міндеттеменің барлық көшірмелерінің `{invoice_id}` | $\text{total} \times (\text{көшірмелер} - 1)$ | Әрбір қайталанған шоттың `doc_id` |
| **Төлемдерді бөлу** | `payment_allocation` | `{invoice_id, payment_id}` | $\text{талап етілетін} - \text{жазылған}$ бөлініс | Шот құжаты, төлем құжаты, дебиторлық қарыз жолдары (+ FX жолы) |
| **Валюта бағамының қатесі** | `fx_mismatch` | `{payment_id}` | $|\text{жазылған} - \text{талап етілетін}|$ | Төлем құжаты, саясат таңдаған FX жазбасы, `fx_clearing` жолы |
| **Кезеңнің сәйкессіздігі (Cutoff)** | `cutoff` | `{invoice_id}` | Шоттың толық сомасы | Шот құжаты, сәйкес кіріс (revenue) жолы |

## Қазылар адаптерінің интерфейсі (`judge_adapter.py`)

[`judge_adapter.py`](judge_adapter.py) тапсырма спецификациясында көрсетілген ресми интерфейсті жүзеге асырады:

```python
import judge_adapter

# 1. Seed пен конфигурация бойынша эпизод құру
judge_adapter.generate_episode(seed=42, config=config, output_dir="out/episodes/eval_01")

# 2. Ортаны құру
env = judge_adapter.make_env()
obs, info = env.reset(seed=42, options={"mode": "closed", "episode_dir": "out/episodes/eval_01"})

# 3. Құралдар арқылы қадам жасау (closed режимінде сыйақы әрдайым 0.0)
obs, reward, terminated, truncated, info = env.step({
    "name": "list_records",
    "args": {"table": "ledger", "cursor": None, "limit": 50}
})

# 4. Жасырын ақиқат бойынша қорытындыларды бағалау
score = judge_adapter.score_episode("out/episodes/eval_01", findings=findings, inspection_steps=18)
```
