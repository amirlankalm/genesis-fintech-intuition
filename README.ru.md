# Genesis FinTech: RL-среда для моделей финансового аудита

[English](README.md) · **Русский** · [Қазақша](README.kk.md)

**Команда Intuition · Genesis Hackathon 2026 (кейс FinTech: «RL-среды для дообучения моделей финансового аудита»)**

Мы — **команда Intuition**. Вот наше решение: воспроизводимый мир обучения с подкреплением (Reinforcement Learning) для дообучения и тестирования ИИ-аудиторов.

В реальном финансовом аудите языковые модели не имеют права галлюцинировать или угадывать: каждое замечание должно быть строго подтверждено первичными документами и бухгалтерскими проводками, а ложное обвинение столь же опасно, как и пропущенная ошибка. Мы создали среду, совместимую со стандартом Gym, где детерминированный генератор создаёт финансовые книги компании за отчётный период, вносит реалистичные бухгалтерские ошибки и правдоподобные ложные следы (decoys), позволяет агенту расследовать данные через 5 строгих инструментов и оценивает выводы агента алгоритмом максимального паросочетания в двудольном графе с официальной функцией награды.

> [!NOTE]
> **100% синтетические данные:** Всё генерируется детерминированно из seed. Никаких реальных компаний, людей, банков, карт или платёжных реквизитов не используется.

**Сроки хакатона:** Проект разработан и валидирован в период хакатона (19–20 ноября 2026 г.). Полностью согласован с финальными спецификациями кейса и официальными определениями проверок от 20 ноября (`judge_adapter.py`, соглашения matcher M01–M12, сценарии D01–D20).

```bash
make docker-check
```
Или напрямую через Docker:
```bash
docker build -t genesis-audit-env . && docker run --rm --network none --cpus 2 --memory 4g genesis-audit-env
```

Без Docker (macOS / Linux, с установленным [uv](https://docs.astral.sh/uv/)):
```bash
uv sync --frozen   # Python 3.11+; зависимости зафиксированы в uv.lock
make check         # lint, mypy, тесты с покрытием, self-check
make judge         # запуск baselines и решателя через judge_adapter.py + conformance-тесты
```

Рабочая директория: корень репозитория (`/app` в контейнере). После `uv sync` сеть не требуется, GPU и платные внешние API не нужны.

## 🧠 Как устроена система

Решение разделено на 5 ключевых уровней:

```
Seed + Конфиг ──► Симуляция бизнес-процессов ──► Чистые бухгалтерские книги
                                                         │
                                                         ▼
                         Инъекция 4 семейств ошибок + ложные следы (Decoys)
                                                         │ (Запись в provenance.json)
                                                         ▼
                                 Истинный ответ по опубликованным правилам
                                                         │
ИИ-аудитор ◄── 5 инструментов (reset/step) ── Книги ──► Двудольный Matcher ──► Награда
```

1. **Симуляция компании:** Сначала моделируется жизненный цикл бизнеса: клиенты, валюты, временные зоны и сделки. На их основе формируются сбалансированные бухгалтерские книги методом двойной записи.
2. **Детерминированное внесение ошибок:** Ошибки отражают человеческий фактор (дубликаты счетов, неразнесённые платежи, ошибки курсов валют, сдвиги отчётных периодов). Каждое изменение фиксируется в `provenance.json` — откат изменений полностью восстанавливает идеальные книги.
3. **Реалистичные ложные следы (Decoys):** Реальный бизнес полон сложных, но законных ситуаций. Мы генерируем частичные оплаты, возвраты, повторяющиеся абонентские платежи и сдвиги часовых поясов, чтобы отсекать наивные эвристики.
4. **Инструменты агента:** Агент взаимодействует со средой через стандартный интерфейс `reset()` и `step()`, используя 5 безопасных инструментов:
   - `list_records(table, cursor, limit)`: постраничное чтение таблиц `ledger`, `invoices`, `payments`, `fx`.
   - `get_record(table, record_id)`: получение конкретной записи или курса валюты.
   - `get_document(doc_type, doc_id)`: чтение исходного документа (счёт или платёж в JSON).
   - `calculator(expression)`: безопасный строковый калькулятор для точной арифметики (`"0.1+0.2"` → `"0.3"`).
   - `submit(findings)`: отправка финального аудиторского отчёта.
5. **Максимальное паросочетание и скоринг:** Замечание засчитывается только при полном совпадении типа ошибки, затронутых ID, суммы, валюты и набора доказательств. Оценка строится на алгоритме максимального двудольного паросочетания с детерминированным разрешением коллизий.

## 🔍 Четыре семейства ошибок

| Ошибка из кейса | Наш `type` | `affected_ids` | Сумма (`claimed_amount_minor`) | Минимальный набор доказательств |
|---|---|---|---|---|
| **Дубликаты счетов** | `duplicate_invoice` | `{invoice_id}` всех копий обязательства | `total × (копий - 1)` | doc_id каждой копии счёта |
| **Разнесение платежей** | `payment_allocation` | `{invoice_id, payment_id}` | разница между нужной и записанной суммой | Документ счёта, документ платежа, строки дебиторской задолженности (+ строка FX) |
| **Курс валюты / дата FX** | `fx_mismatch` | `{payment_id}` | модуль ошибки пересчёта | Документ платежа, ключ FX по правилам политики, строка `fx_clearing` |
| **Период отсечения (Cutoff)** | `cutoff` | `{invoice_id}` | Полная сумма счёта | Документ счёта, соответствующая строка выручки в главной книге |

### Взаимодействующие сценарии:
- `cutoff_and_allocation`: счёт отнесён к неверному периоду, а платёж по нему частично разнесён в иностранной валюте на стыке периодов.
- `duplicate_then_cutoff`: дубликат счёта ошибочно перенесён в чужой отчётный период.

## ⚖️ Адаптер для жюри (`judge_adapter.py`)

```python
import judge_adapter

# 1. Генерация эпизода
judge_adapter.generate_episode(seed=42, config=config, output_dir="out/episodes/eval_01")

# 2. Создание среды
env = judge_adapter.make_env()
obs, info = env.reset(seed=42, options={"mode": "closed", "episode_dir": "out/episodes/eval_01"})

# 3. Шаг агента (в закрытом режиме промежуточная награда всегда 0.0)
obs, reward, terminated, truncated, info = env.step({
    "name": "list_records",
    "args": {"table": "ledger", "cursor": None, "limit": 50}
})

# 4. Оценка выводов
score = judge_adapter.score_episode("out/episodes/eval_01", findings=findings, inspection_steps=18)
```
