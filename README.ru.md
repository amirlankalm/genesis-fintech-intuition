# Genesis FinTech: RL-среда для моделей финансового аудита

[English](README.md) · **Русский** · [Қазақша](README.kk.md)

**Команда Intuition · Genesis Hackathon 2026 (кейс FinTech: «RL-среды для дообучения моделей финансового аудита»)**

Мы — **команда Intuition**. Вот наше решение: воспроизводимый мир обучения с подкреплением (Reinforcement Learning), совместимый со стандартом Gym, для дообучения и оценки ИИ-аудиторов.

В реальном финансовом аудите автономные агенты не могут полагаться на спекулятивные догадки или галлюцинации: каждое несоответствие должно подтверждаться неизменяемыми первичными документами и проводками, а ложные срабатывания создают огромные финансовые риски. Мы создали среду, где детерминированный генератор формирует финансовую отчётность компании за период, вносит реалистичные бухгалтерские ошибки и ложные следы (decoys), предоставляет пять инструментов инспекции и оценивает выводы агента строгим алгоритмом максимального двудольного паросочетания с официальной функцией награды.

> [!NOTE]
> **Синтетические данные:** Все контрагенты, банковские счета и транзакции генерируются детерминированно из seed. Реальные данные компаний или платёжные реквизиты не используются.

**Сроки:** Проект разработан и валидирован во время хакатона (19–20 ноября 2026 г.). Полностью соответствует спецификации кейса и официальным определениям проверок от 20 ноября (`judge_adapter.py`, правила matcher M01–M12, сценарии D01–D20).

## Быстрый старт

### Локальный запуск (Python 3.11+, uv)

```bash
uv sync --frozen   # установка зафиксированных зависимостей
make check         # lint, mypy, pytest с покрытием, self-check
make judge         # запуск baselines и решателя через judge_adapter.py + conformance-тесты
```

### Запуск в Docker (автономные лимиты: 2 CPU, 4 ГБ RAM, без сети)

```bash
make docker-check
```

Или напрямую через Docker без `make`:

```bash
docker build -t genesis-audit-env . && docker run --rm --network none --cpus 2 --memory 4g genesis-audit-env
```

Все операции выполняются локально из корня репозитория (`/app` в контейнере). Сеть после установки зависимостей не требуется, внешние API и GPU не используются.

## Архитектура системы

Архитектура среды разделяет бизнес-логику, мутацию состояния, инспекцию агентом и формальную оценку на пять независимых слоёв:

```
Seed + Конфиг ──► Симуляция бизнес-процессов ──► Чистые бухгалтерские книги
                                                         │
                                                         ▼
                         Инъекция 4 семейств ошибок + ложные следы (Decoys)
                                                         │ (Запись в provenance.json)
                                                         ▼
                                 Истинный ответ по опубликованным правилам
                                                         │
ИИ-аудитор ◄── 5 инструментов (reset/step) ── Книги ──► Двудольный Matcher ──► Награда
```

1. **Симуляция компании:** Генерирует контрагентов, график сделок, мультивалютные расчёты и курсы валют. На их основе формируются сбалансированные бухгалтерские книги методом двойной записи (`ledger.csv`, `invoices.jsonl`, `payments.jsonl`, `fx.csv`). Все суммы выражены точными целыми числами в минорных единицах валют (центы, тиыны, иены) для исключения погрешностей чисел с плавающей точкой.
2. **Детерминированное внесение ошибок:** Вносит человеческие операционные ошибки (дублирование счетов, неразнесённые оплаты, ошибки курсов валют, сдвиги периодов отсечения). Каждое изменение фиксируется в `provenance.json` — инверсия истории математически восстанавливает чистые книги.
3. **Реалистичные ложные следы (Decoys):** Включает законные нетривиальные случаи (периодические счета с одинаковыми суммами, разбиение платежей на части, возвраты, сдвиги часовых поясов), чтобы отсекать наивные эвристики.
4. **Инструменты агента:** Реализует жизненный цикл Gym (`reset` и `step`). Пространство действий строго ограничено пятью инструментами:
   - `list_records(table, cursor, limit)`: постраничное чтение таблиц с детерминированными курсорами (до 50 строк).
   - `get_record(table, record_id)`: точечный запрос записи по первичному ключу.
   - `get_document(doc_type, doc_id)`: чтение исходного документа (JSON счёта или платежа).
   - `calculator(expression)`: безопасный строковый арифметический калькулятор.
   - `submit(findings)`: финальная отправка структурированного аудиторского отчёта.
5. **Двудольное паросочетание и скоринг:** Замечание засчитывается только при полном совпадении типа ошибки, ID, суммы, валюты и доказательств. Оценка строится как задача о максимальном двудольном паросочетании с детерминированным разрешением коллизий.

## Семейства бухгалтерских ошибок

Каждое правило формализовано в `policy.json` и разрешимо по открытым документам:

| Семейство ошибок | `type` в среде | `affected_ids` | Сумма (`claimed_amount_minor`) | Минимальный набор доказательств |
|---|---|---|---|---|
| **Дубликаты счетов** | `duplicate_invoice` | `{invoice_id}` всех копий обязательства | $\text{total} \times (\text{копий} - 1)$ | `doc_id` каждого дубликата счёта |
| **Разнесение платежей** | `payment_allocation` | `{invoice_id, payment_id}` | $\text{требуемая} - \text{записанная}$ сумма | Документ счёта, документ платежа, строки дебиторской задолженности (+ строка FX) |
| **Курс валюты / дата FX** | `fx_mismatch` | `{payment_id}` | $|\text{записанная} - \text{требуемая}|$ | Документ платежа, ключ курса валюты, строка `fx_clearing` в главной книге |
| **Период отсечения (Cutoff)** | `cutoff` | `{invoice_id}` | Полная сумма счёта | Документ счёта, соответствующая строка выручки в главной книге |

### Взаимодействующие сценарии
- `cutoff_and_allocation`: счёт за пределами периода в сочетании с частичным разнесением валютного платежа на стыке периодов.
- `duplicate_then_cutoff`: дубликат счёта ошибочно отнесён к чужому отчётному периоду.

## Интерфейс адаптера жюри (`judge_adapter.py`)

[`judge_adapter.py`](judge_adapter.py) реализует официальный интерфейс автоматизированного тестирования:

```python
import judge_adapter

# 1. Генерация эпизода по seed и конфигурации
judge_adapter.generate_episode(seed=42, config=config, output_dir="out/episodes/eval_01")

# 2. Создание стандартизированной среды
env = judge_adapter.make_env()
obs, info = env.reset(seed=42, options={"mode": "closed", "episode_dir": "out/episodes/eval_01"})

# 3. Шаг агента через инструменты (в закрытом режиме награда всегда 0.0)
obs, reward, terminated, truncated, info = env.step({
    "name": "list_records",
    "args": {"table": "ledger", "cursor": None, "limit": 50}
})

# 4. Внешняя оценка выводов по скрытой истине
score = judge_adapter.score_episode("out/episodes/eval_01", findings=findings, inspection_steps=18)
```

- **Закрытый режим оценки:** Во время тестирования промежуточные награды равны `0.0` для предотвращения утечки состояния.
- **Лимиты ресурсов:** 100 шагов (включая `submit`) и 60 секунд на эпизод.
- **Ограничение доказательств:** Не более 10 ID доказательств на одно замечание.

## Тестирование и верификация

```bash
uv run pytest                 # Полный набор тестов: ~1 240 тестов
uv run pytest tests/jury      # Тесты соответствия официальным проверкам
```

- **Официальные проверки:** Валидирует проверки C01–C20 (контракт), D01–D20 (сценарии), M01–M12 (matcher), P01–P20 (парные проверки).
- **Инварианты верификации:**
  - Подтверждённые доказательствами замечания строго опережают молчание на ошибочных книгах.
  - Молчание строго опережает ложные срабатывания на чистых книгах.
  - Повторяющиеся замечания не приносят баллов и штрафуются как ложные срабатывания.
  - Угаданные ID и некорректные структуры штрафуются.
  - Каждый эпизод детерминированно воссоздаётся байт в байт из своего seed.
